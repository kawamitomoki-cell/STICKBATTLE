# 最強CPU：距離で読まれにくい行動へ

基準 `be5accf`。最強以外の難易度設定、反応遅延、キャラ性能、通信プロトコルは変更しない。

## 実装

- 最強ではpressure/ambush/mixの戦術モードを90～209フレーム保持。毎判断でモードを引き直さず、攻めの流れを作る。
- 有効性スコアが首位から9以内の実行可能な候補に絞り、重み付きで選択。直近4手の同技反復を減点。確定反撃では選択幅を狭くする。
- 通常・特殊に加え20～36フレームの中溜めを候補に追加。長い溜めは大きな隙、または接近してくる敵への置き技として評価。
- 遅延観測で回避やカウンターを確認したら溜め解除を少し待ち、硬直を確認したら早めに離す。66フレームで強制的に入力を離すため、CPUが溜め延長で自分からオーバーヒートしない。
- 待ち伏せモードでは短い踏み込み/引きを最大12フレーム、次回まで90フレーム以上空けて行う。崖への移動は既存の安全判定を通す。敵が攻撃すれば通常防御へ戻る。
- 相手の公開された溜めが最大近く、近距離・正面ならカウンターを準備する。五条・悟空の貫通する可能性がある攻撃はこの読みカウンターから除外する。
- 弓の遠距離攻撃にも単発と5本、長押し時間の差を付ける。
- 五条は75%の選択で基本の最大評価技を維持し、遅い技の失敗を増やしすぎない。狂戦士は新しいモード付き技選択・誘い移動・溜め延長を適用しない（模擬対戦で悪化したため）。共通の最大溜め条件修正・過熱防止は適用される。

入力を読んだり、その場で無敵・攻撃力を付与したりしない。相手の状態は既存の8フレーム遅延観測から判断する。

## 検証

ビルド・整合性確認成功。自動テスト70件成功、失敗0・スキップ0。同距離の候補で3種の技を選ぶこと、射程外候補を選ばないこと、モードの持続、誘い終了、最大近くの溜めに対するカウンター、過熱前解除のテストを追加。

`node scripts/benchmarks/expert-duel.mjs cpu-expert-v2.txt` で直前の公開版と直接対戦できる。基準コードと結果は `scripts/benchmarks/cpu-expert-v2.txt` / `mixup-results.json`。
17キャラ×6固定シード、同キャラ3ストック、標準ステージ、左右交代、最大3600フレーム。
**60勝40敗2時間切れ**。人間相手の勝率や楽しさを保証しない。
力士2勝4敗、五条2勝4敗、承太郎2勝4敗、狂戦士1勝5敗など、キャラ別の悪化・課題も残る。対人の「読みにくさ」はまだ実測していない。複数ステージ、実機、通信込みの負荷も未検証。

## 次の調整

プレイヤーがどう対応したかを基に、誘いの発生率と技選択の幅を調整する。狂戦士の読み合いは遅い斧を軸に別調整が必要。長い溜めはリスクが高く、無条件に混ぜれば強くなるわけではない。スコアで候補を制限してもなお失敗する余地は残している。
