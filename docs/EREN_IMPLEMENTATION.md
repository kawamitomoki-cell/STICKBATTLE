## 実装内容

`src/game/14-eren.js` に固有データ、状態、入力、描画、通信の境界、CPUアダプタを分離した。

|入力|人間形態|進撃の巨人|
|---|---|---|
|通常|双剣2連撃、5×2ダメージ|拳14、左右の腕を交互に使用|
|溜め|回転斬り10～16|鉄拳18～28、長い予備動作と後隙、衝撃波・ローカル8フレームのヒットストップ|
|特殊|足場へワイヤー、アンカー・2本のケーブル・牽引加速・ガス|掴み→24フレームの拘束→16ダメージの投げ|
|横特殊|ワイヤー接続が成功した場合のみ双剣急襲14、外した後隙あり|タックル18、後隙大、土煙|
|上特殊|上の足場へワイヤー復帰。空中1回。地上ワイヤーのクールタイムから独立|対空アッパー18。移動復帰には使わない|
|下特殊|ゲージ100で巨人化|硬質化120フレーム、被ダメージ30%減、再使用360フレーム|
|カウンター/回避|共通入力・共通ルールを維持|共通ルール。巨人でも完全無敵にはしない|

人間は速度1.15、重量係数1.05（標準よりやや軽い）。巨人は描画3倍、移動.62、ジャンプ.68、重量係数.48。硬質化中は移動.32、特殊/溜め強攻撃を使えず、通常の拳も終了51フレームに遅くなる。

エレンは双剣/立体機動装置を専用装備とし、落ちている武器は拾わない。既存キャラの武器使用は変えない。

## 巨人化・ゲージ

- 自然蓄積なし。通常命中+6、強攻撃+10。特殊も6～10。被弾は実ダメージ×2。定数はERENに集約。
- 同一攻撃/同一対象の多段ヒットを1回の加算に制限。通信上の遅延した命中通知も攻撃トークンで区別し、履歴は上限128件。
- 変身中/解除疲労中は蓄積しない。18秒＝1080回の戦闘更新。変身演出84フレーム、全体フリーズ・時止め・試合停止で時間を消費しない。
- 解除で蒸気、ゲージ0、60フレーム疲労。次の残機は獲得済みゲージを最大50だけ保持し、形態・拘束・ワイヤー・硬質化は初期化。最終撃墜と新試合ではゲージも0。
- ワイヤー成功時にガス回避を表す4フレームの短い無敵。連続飛行にはならず、アンカーは実在する足場の範囲内、距離340まで・26フレーム・通常再使用65フレーム。接続できなければ移動しない。

## 専用判定・拘束

巨人の身体は幅68・高さ207の専用矩形、攻撃は巨人のサイズと技データの拳位置で判定。小さな相手の足元も攻撃できる。通常キャラは従来の円/線分判定を維持。
うなじは背後上部の半径14程度の点、命中時1.2倍。近接・通常弾・アニメ系飛び道具から判定する。
足の座標を変身時に動かさず、接地は既存の一方向足場を使う。既存ゲームに固体壁や頭部の天井衝突はなく、上の足場と巨人の上体が視覚的に重なる場合がある。専用の天井空間・全ステージでの大型キャラ調整は残課題。

掴みは1攻撃1対象。受け手の所有端末が拘束・投げダメージを確定。味方・無敵・巨人同士への掴みを拒否する。攻撃者の被弾/気絶/消滅/変身解除、距離異常で拘束を解除。重複トークンを拒否し、拘束タイマーを上限24に制限する。

## 描画・音・UI

オリジナルのベクター描画と既存の合成効果音のみ。原作画像・音声・BGMは導入していない。
手を噛む→黄金の稲妻→煙/シルエット→咆哮を表す低音・リング→ATTACK TITAN表示の段階的な画面内カットイン。実際の音の聞こえ方は未評価。
「光刺激を抑える」設定を追加。巨人化のフラッシュを省き、画面暗転も軽減する。既存演出全般を作り替える設定ではない。
選択一覧・ポートレート・専用説明、TITAN GAUGE、残秒、残り3秒の警告色、解除疲労、既存タッチ操作のラベルを用意した。

## CPU・オンライン

AI_CHARACTER_PLAN/AI_SKILLSと既存Utility AIへ追加。人間形態の急襲・双剣、巨人の拳/掴み/タックルを評価。ゲージMAXだけで即発動せず、敵の距離・被ダメージ・残機差・足場幅を確認して変身する。硬質化は近い大技への防御に限定。
通信は既存の所有者権威・イベント・スナップショットを利用し、形態/ゲージ/残時間/硬質化/ワイヤー/拘束/左右パンチ順を追加。変身開始は既存シネマティック、解除はイベント＋スナップショット。再受信時の値・地形接続を検証。掴み要求と変身の送信者も確認。
プロトコルは `SBO_NET_EREN_V31`。公開する場合は全員の再読み込みと新規ルームが必要。

## 検証結果

- `npm run build` / `npm run check` 成功。
- `npm test`：88件成功、失敗0、スキップ0（既存更新と18体目の共通試験、エレン専用17件を含む）。
- 専用試験：全入力、2連撃/ゲージ上限、被弾蓄積、1080フレーム/停止、ワイヤーの地形接続と復帰回数、巨人の身体/足元攻撃、うなじ、硬質化、掴み/重複/味方/無敵/解除、KO/残機、状態復元、2クライアント模擬通信、CPU変身判断。
- Chromium＋p5 1.9.0で人間/巨人/変身を実描画。PC幅1280、タッチ付きスマホ幅390で実行時エラー0、横スクロールなし。タッチの下特殊で変身、光刺激抑制を有効にしたカットインも確認。
- CDN制限のためブラウザ試験はnpmから取得した同一p5をローカル配信し、Firebase/QRCodeの外部scriptを除いた一時ページで実施。リポジトリのHTMLは正規ビルドのまま。実Firebase検証ではない。
- 1/7 CPUを巨人混在の固定更新で1200フレーム実行し、数値破綻なし。描画・通信を除く合計約50/166ms（機器依存、FPS保証ではない）。
- `node scripts/benchmarks/eren.mjs`：既存17体×2シード、3残機、左右交代、標準ステージ、3600フレーム上限。最終結果はeren-results.json。**6勝28敗、変身25回**。CPU変身は確認できたが明確に負け越しており、対人バランス完成とは判断しない。

## 未検証・未完成部分

- 実Firebaseの2端末間での掴み成功/解除/再接続、遅延/切断、オンライン大会の通し試験。
- 実スマホ/ゲームパッド、音響品質、描画・通信込みの多人数FPS、全ステージでの巨大な身体と足場の視覚整合。
- 巨人掴みは拘束/投げまで実装したが、手と対象の位置の遅延時補間や専用投げカメラは未調整。
- エレンCPUと人間形態の性能は負け越しが大きく調整必須。ゲージ獲得・復帰・急襲の命中率・巨人中の防御行動を重点的に調整する。
- カットイン/咆哮/肉体モーションの原作らしい迫力は初期ベクター表現の段階。見た目の最終品質確認が必要。
