# 金木：捕縛から追撃への空白を修正

捕縛時間が18Fと短く、金木側は通常の硬直と「命中後の押し直し」が残っていた。引き寄せ完了付近で相手が逃げる/反撃する一方、先に押した特殊は追撃として受理されなかった。

- 捕縛成立時に相手の攻撃・カウンター等を即座に解除。拘束中は相手の行動を進めない。
- 引き寄せを最大30Fへ延長し、自然解放後に8F以内の短い硬直を置く。被弾・KO・形態変更・術者不在による中断にはこの硬直を追加しない。
- 捕縛動作の4F目以降は24Fの先行入力を受付。成立確認後は通常の後隙を待たずに特殊・上特殊・攻撃へ移れる。
- 成立を被弾側の所有端末から金木側へ通知。送信者、攻撃ID、現在の捕縛動作を検証し、別の技や空振りの硬直を不正に解除できない。再送は同じ記録に反映するだけで、追加ダメージや回復を与えない。
- 空振りの48F動作/特殊待ち80F、捕縛前の無敵/回避/カウンター、アーマー・巨人への代替打撃、120Fの再捕縛制限は維持。

`npm run build`、`npm run check`、`npm test` 全186件成功。捕縛直後の相手の攻撃解除、命中前の先行入力→成立直後の乱舞、空振りの隙、拘束中の反撃拒否、有限の解除硬直、不正成立通知を追加検証。2所有端末の模擬通信で成立通知/重複受信も成功。

PC/スマホ相当の既存ブラウザー操作試験で捕縛→特殊連打→締めスマッシュ（累積40）・復帰・覚醒が成功、実行時エラーと横はみ出し0。実Firebase越しの遅延・再接続、実スマホ・対人バランスは未検証。通信条件にかかわらず必ず追撃が確定するとは保証しない。

プロトコルは `SBO_NET_KANEKI_CAPTURE_V43`。公開反映後は全員再読み込み・新規ルームが必要。
